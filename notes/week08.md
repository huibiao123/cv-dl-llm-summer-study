# 大模型与普通深度学习模型的区别

“大模型”主要指 **大语言模型（LLM）**，例如 GPT、Claude、Gemini、Llama 等。
核心的区别在于：**模型规模、训练数据规模、训练目标和使用方式发生了巨大变化。**
## 案例 
```
输入：
“请解释一下什么是卷积神经网络”
        ↓
       LLM
        ↓
输出：
“卷积神经网络是一类主要用于处理具有网格结构数据的神经网络……”
```
解释：其逻辑为根据前面的内容，预测接下来最可能出现什么 Token。
```
例如：
今天天气很
模型可能预测：
好
然后继续：
今天天气很好，
预测：
适合
然后：
今天天气很好，适合
预测：
出去
```
## 分类
```
人工智能
└── 机器学习
    └── 深度学习
        ├── CNN
        ├── RNN
        ├── Transformer
        │    └── 大语言模型
        └── ...
```
## 总结
大模型是规模极大、使用 Transformer 架构、经过海量数据训练的深度学习模型。

# Transformer
## 思想
利用 Attention 机制来处理序列中的不同位置之间的关系。

## 案例
```
假设一句话：
> “小明把书放在桌子上，因为他觉得桌子比较干净。”
模型需要理解：
> “他”指的是谁？
这要求模型能够建立：
他 ←→ 小明
这种远距离关系。
传统的 RNN 是按照顺序：
小明 → 把 → 书 → 放 → 在 → 桌子 → 上 → ...
一个一个处理。
Transformer 则可以通过 Attention：
小明 ───────────────┐
                    ↓
他 ←──── Attention ──┘
直接判断：
> “他”应该重点关注“小明”。
```
# Attention

理解：Attention=我现在处理这个词的时候，应该重点看前面的哪些词？
其中有三个概念：
- **Query：我现在想找什么？**
- **Key：我这里有什么？**
- **Value：如果你关注我，我提供什么信息？**
```
例如：
> “苹果很好吃，因为它很甜。”
处理“它”：
Query：我现在这个“它”应该对应谁？
        ↓
Key：
“小明”
“苹果”
“桌子”
……
        ↓
计算匹配程度
        ↓
苹果获得较高 Attention
        ↓
Value 提供“苹果”的相关信息
```
这就是 Attention 的基本思想。

# Token

## 理解
Token 可以理解成模型处理文本时使用的基本单位。
（注意：Token 不完全等于“一个汉字”，也不完全等于“一个单词”。具体怎么切，取决于模型使用的 **Tokenizer（分词器）**。）

# Embedding

## 理解
```
Token ID 本身没有什么语义。
例如：
猫 = 3821
狗 = 9281
汽车 = 1742
这些数字：
> 3821、9281、1742
本身并不能告诉神经网络“猫”和“狗”很相似。
因此需要 Embedding。
```
## 实际案例
```
Embedding 就是把 Token 变成向量
例如：
猫
↓
[0.21, -0.13, 0.72, ...]
狗
↓
[0.19, -0.10, 0.69, ...]
汽车
↓
[-0.82, 0.51, -0.31, ...]
于是：
猫 ←→ 狗
在向量空间中的关系可能比：
猫 ←→ 汽车
更接近。
```

# Prompt
## 理解
你提供给大模型的输入指令/上下文。
```
例如：
请解释一下什么是 Transformer。
这是 Prompt。
再比如：
你是一名计算机专业教师。
请用大学生能够理解的方式解释 Transformer。
不要使用过于复杂的数学公式。
这也是 Prompt。
```
# 上下文窗口
## 理解
模型一次能够“看到并处理”的 Token 总量。
```
例如：
你：
我之前说过一个项目……
↓
历史对话
↓
你：
现在请继续修改那个项目。
↓
模型根据上下文理解：
“那个项目”是什么
这就是上下文发挥作用。
```
# 温度参数（Temperature）
## 理解
Temperature 是模型生成 Token 时的随机性/多样性
```
Temperature 低
↓
更保守
更确定
更稳定
Temperature 高
↓
更随机
更多样
更容易产生意外结果
```
# 幻觉问题（Hallucination）
## 理解
模型生成了看起来合理、语言流畅，但实际上错误、虚构或没有依据的信息。
```
例如你问：
> “2020 年某大学发表的《XXX》论文主要结论是什么？”
如果这个论文根本不存在，模型却回答：
> “该论文由张某某发表于 Nature，研究发现……”
这就是典型幻觉。
```
## 原因
```
问题在于：
LLM 的核心生成机制并不是一个数据库查询系统。
它主要是在做：
> 根据上下文预测下一个 Token。
所以：
合理 ≠ 真实
模型非常擅长生成：
> “听起来像正确答案的文本”。
但这并不意味着它一定进行了现实世界意义上的事实核验。
```
# 用例子来区分普通分类模型和生成式大模型

|场景|普通分类模型|生成式大模型|
|---|---|---|
|图像|输入猫的图片 → `猫`|输入“描述这张猫的图片” → 生成一段描述|
|邮件|输入邮件 → `垃圾邮件 / 正常邮件`|输入邮件 → 生成“这是一封疑似诈骗邮件，因为……”|
|情感|输入“这个电影太好看了” → `正面`|输入评价 → 生成“这条评价表达了积极情绪，主要原因是……”|
|文章|输入文章 → `体育 / 科技 / 娱乐`|输入“写一篇关于人工智能的文章” → 直接生成文章|
|问答|输入问题 → 从固定类别中选择|输入“什么是 Transformer？” → 生成完整解释|
## 例子 1：图片识别
**普通分类模型：**
```
猫的图片
   ↓
CNN / ResNet
   ↓
[猫: 0.95, 狗: 0.03, 鸟: 0.02]
   ↓
   猫
它的任务是：
判断输入属于哪个已经定义好的类别。

**生成式大模型：**
猫的图片
   ↓
多模态大模型
   ↓
“一只橘色的猫趴在沙发上，正在看向镜头。”
它不是从“猫、狗、鸟……”中选择一个，而是在生成新的文本。
```
## 例子 2：垃圾邮件
输入：
“恭喜您获得100万元大奖，请立即点击链接领取！”
**分类模型：**
垃圾邮件：98%
正常邮件：2%
最终：垃圾邮件

**大模型：**
可以要求：“判断这封邮件是否可疑，并说明理由。”
模型可以生成：“这封邮件具有明显的诈骗特征，包括夸大奖励金额、要求立即操作以及诱导点击链接等。”
区别在于：
**分类模型回答“它属于哪一类？”**
**生成模型回答“关于它，我可以生成什么内容？”**

## 例子 3：电影评价
输入：“这部电影剧情非常精彩，但是结局有点仓促。”
**普通分类模型：**
正面：0.72
中性：0.20
负面：0.08
最终：正面评价

**生成式大模型：**
可以要求：“总结这条评价。”
输出： “评价总体积极，认为电影剧情精彩，但对结局处理有所不满。”
还可以要求：“提取优点和缺点。”
输出：
优点：剧情精彩
缺点：结局仓促

## 例子 4：文章处理
输入一篇新闻。
**普通分类模型：**
输入：判断这篇新闻属于什么类别
输出：科技新闻
也就是：文章 → 类别

**生成式大模型：**
可以要求：
 “用100字总结这篇新闻。”
于是：
```
文章
 ↓
大模型
 ↓
摘要 / 改写 / 翻译 / 问答 / 信息提取……
```
同一个模型可以完成很多不同的生成任务。

## 例子 5：回答问题
假设问题：
"为什么 Transformer 中需要 Attention？”
**普通分类模型**
通常需要预先定义答案类别，例如：
A：需要
B：不需要
C：不知道
那么模型只能完成：
问题 → A / B / C

**生成式大模型**
```
问题
 ↓
Token化
 ↓
Transformer
 ↓
预测 Token
 ↓
预测 Token
 ↓
预测 Token
 ↓
……
 ↓
完整回答
```
最终生成：
“Attention 可以让模型动态关注输入序列中与当前 Token 关系更密切的部分，从而更好地建模长距离依赖关系……”

# 总结 LLM 能做什么&LLM 不能做什么

## LLM能做什么
LLM 的核心能力是**理解输入内容，并根据上下文生成新的内容**。
- **文本生成**：写文章、写代码、生成解释、生成对话。
- **文本理解**：分类、摘要、情感分析、信息提取。
- **文本转换**：翻译、改写、润色、扩写、压缩。
- **问答与推理**：回答问题、分析材料、进行一定程度的逻辑推理。
- **多轮对话**：结合上下文理解前面的内容，并继续完成任务。
- **多任务处理**：同一个模型可以通过不同 Prompt 完成不同任务，而不需要为每一种任务单独训练一个分类器。
可以概括为：
**传统模型通常针对一个明确任务输出固定形式的结果，而 LLM 可以根据 Prompt 灵活地理解和生成内容。**

## LLM 不能做什么
LLM 的输出**不等于客观事实，也不等于绝对正确的推理结果**。
- **不能保证事实正确**：可能产生幻觉，生成虚构的人物、论文、数据或事件。
- **不能保证信息实时**：模型本身不一定知道最新发生的事情，需要搜索、数据库等外部工具辅助。
- **不能保证推理永远正确**：复杂的数学、逻辑、长链条推理仍可能出错。
- **不能把自己当作事实数据库**：LLM 主要进行概率性的 Token 生成，而不是简单地从数据库中检索答案。
- **不能仅凭语言流畅判断正确性**：回答可能“非常像正确答案”，但实际上没有事实依据。
- **不能保证完全理解用户意图**：Prompt 含义不清、上下文不足时，模型可能产生错误理解。
最重要的一句话：
**LLM 擅长生成“合理的语言”，但“合理”不等于“真实”，“流畅”也不等于“正确”。**
